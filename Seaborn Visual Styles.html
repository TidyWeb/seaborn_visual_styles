Visual atlas + working reference

Seaborn gives statistics
a visual vocabulary.

Seaborn is narrower than Matplotlib by design. It concentrates on high-level statistical graphics: relationships, distributions, categories, regression and structured grids. That narrower range is not a weakness. Each family has many switches for changing the view—kind=, hue=, style=, size=, faceting, palettes, scales and statistical treatments—so the same basic idea can answer many different questions.

01 · Data vocabulary

A visual vocabulary needs a data vocabulary

The word data covers several different jobs. A Python dtype tells you how a value is stored; it does not, by itself, tell you what that value means in a chart.

A measured amount can be placed on a numeric axis. A category names a group. An ordered category has a sequence without trustworthy numeric gaps. A date carries order and intervals. An identifier names a row or entity, but is not a measurement. Seaborn becomes easier when we ask what role each field plays before deciding how to show it.

Measurementprice = 9.95How much? How far? How many? Differences between values carry meaning, so measurements often belong on an axis or a visual scale.
Categorymaterial = "leather"Which named group? Categories separate observations; they are not quantities to add or average. They can become colour, style, order or facets.
Ordered categorysize = "medium"The levels have a meaningful order, but the gaps between them are not automatically equal numeric distances.
Timepurchased = 12 MarchWhen did it happen? Time carries sequence and intervals, which makes it useful for ordered displays such as line plots.
Identifiertransaction_id = 10482Which row or entity is this? An identifier helps us locate something, but usually should not be treated as a measured axis.
Worked row · one purchase

One row can contain all of these roles at once. They are all data, but they do different jobs:

price = 9.95measurement
item = "gloves"category
purchased = "Tuesday 12 March"time
transaction_id = 10482identifier
Keep three questions separate: how values are stored (dtype), what they mean in the investigation (their role), and how the rows are arranged (one variable, two variables, groups, long form, wide form or a matrix).
variable roles→data arrangement→question→plotting function→switches

“Are prices spread out?”, “Do materials have different prices?”, “Do price and quantity move together?”, and “Does a fitted trend summarise the pattern?” are different questions about the same general world. That is why a data vocabulary comes before a visual vocabulary.

The extra layer: seaborn.objects

The familiar function interface starts with a chart function and adds data assignments. The newer objects interface starts with a declarative Plot specification, then composes marks, statistical transformations, positional adjustments, facets and scales.

Representative objects call
import seaborn.objects as so

(
    so.Plot(data, x="value", y="score", color="group")
    .add(so.Dots())
    .add(so.Line(), so.PolyFit())
)

Think in layers

Plot maps data. A Mark draws it. A Stat transforms it. A Move adjusts positions. A Scale controls how values become visual properties.

PlotData mappings and layout.
MarkDots, lines, bars, areas or text.
StatAggregation, histograms, KDE or estimates.
MoveDodge, jitter, stack or shift.
ScaleColour, size, coordinates and transformations.
facet()Small multiples from one specification.
02 · Switch glossary

One plotting function, many controlled variations

Each card begins with a named plotting function: for example, sns.scatterplot(). That is the precise Python term for the callable; we can also use plotting method as a friendly shorthand for the major display type.

The function chooses the kind of display. Its keyword parameters—the switches—tell Seaborn how to map data, separate groups, style the marks, apply statistical treatment and arrange the result.

The method / plotting function
sns.scatterplot(x="carat", y="price", data=diamonds)
Read every call in two layers: first identify the plotting function; then read the switches that make this particular version richer or more specific.
Example 02 · Scatterplot with multiple semantics

Start simple, then add meaning

A basic scatter plot needs an x value, a y value and the data source. Example 02 then adds switches that make more variables visible.

Basic call
sns.scatterplot(x="carat", y="price", data=diamonds)
Richer call
sns.scatterplot(
    x="carat", y="price", data=diamonds,
    hue="clarity", size="depth",
    palette="ch:r=-.2,d=.3_r",
    hue_order=clarity_ranking,
    sizes=(1, 8), linewidth=0,
)

hue="clarity" separates groups by colour; size="depth" adds another variable through point size; palette, hue_order, sizes and linewidth refine the treatment.

Data mappingsx= / y= / data=Tell the plotting function which columns or values become the horizontal axis, vertical axis and observations.
Semantic switcheshue= / style= / size=Give extra variables a visual job: colour, marker or line style, and point size or line width.
Ordering and groupinghue_order= / order= / row= / col=Control category order or split the same display into comparable subsets.
Appearancepalette= / color= / alpha= / linewidth=Change the visual treatment without changing the question the display answers.
Statistical treatmentkind= / bins= / stat= / errorbar=Choose the display variant, binning, summary scale or uncertainty treatment where that family supports it.
Layout and destinationheight= / aspect= / ax= / sharex=Control figure proportions, the Matplotlib axes that receives the plot, and whether facets share scales.
04

Relationships

Use these when the question concerns association, continuity or how one variable changes with another.

These displays are useful when two variables may be associated or when an ordered sequence shows change over time. They are less useful when the main information is simply that observations belong to named groups, with no meaningful relationship between two measured axes.

Switch mapHigh-value starter switches for this family—not every keyword in the full API.
kind=relplot can switch between scatter and line.
hue=Map a variable to colour so groups become visible.
style=Map a variable to marker or line style.
size=Map a variable to point size or line width.
row= / col=Facet the same relationship into small multiples.
col_wrap=Wrap many column facets onto multiple rows.

05

Distributions

Use these when the question concerns spread, density, frequency, cumulative position or shape.

These displays are useful when one measured variable is the subject and you want to see its spread, concentration, skew, unusual values or density—for example, delivery times. They are less useful when the main question is how one variable changes with another.

Switch mapHigh-value starter switches for this family—not every keyword in the full API.
kind=displot can switch among histogram, KDE, ECDF and rug views.
bins=Change the number or boundaries of histogram intervals.
stat=Choose counts, probability, density or percent-style summaries.
multiple=Layer, stack, fill or dodge distributions for comparison.
element=Use bars, steps or polygons for histogram construction.
common_norm=Decide whether group densities share a normalisation.

Categorical comparisons

Use these when observations belong to named groups and the comparison is within or between categories.

These displays are useful when observations belong to named groups and you want to compare a measured outcome across those groups—for example, glove price by material or delivery time by weekday. They are less useful when the important structure is a relationship between two continuous measurements.

Switch mapHigh-value starter switches for this family—not every keyword in the full API.

order=Control the order in which categories appear.
hue=Add a second categorical grouping through colour.
dodge=Separate or overlap hue groups within each category.
inner=Choose the summary drawn inside a violin plot.
native_scale=Keep numeric or datetime category positions on their original scale.

07

Regression

Use these when a fitted relationship or its residual pattern is part of the question.

These displays are useful when a fitted relationship can summarise the pattern between variables. A residual is the leftover difference between an observed value and the model’s estimate, so residual views help reveal what the fitted line has not explained. They are less useful as evidence of causation, or when there is no sensible relationship to model.

Switch mapHigh-value starter switches for this family—not every keyword in the full API.
order=Fit a polynomial regression of the chosen order.
hue= / col=Fit and compare models across groups or facets.
logistic=Fit a logistic rather than ordinary linear model.
robust=Use a robust fit when outliers may dominate the ordinary fit.
lowess=Use a locally weighted smooth rather than a parametric model.
errorbar=Control the uncertainty band around an estimate or fit.

Matrices

Use these when values form a rectangular matrix or pairwise structure is best read through colour.

These displays are useful when values already form a meaningful grid, such as correlations between many numeric variables, and colour or clustering can reveal structure. They are less useful for following individual observations row by row.

annot=Write values into heatmap cells when numbers matter.
mask=Hide cells that should not be displayed.
row_colors= / col_colors=Add side colour annotations for groups or metadata.
standard_scale=Scale rows or columns before comparison or clustering.
